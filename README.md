# Unreal Engine 5 Interaction System (example)

A type-agnostic, first-person **interaction system** for Unreal Engine 5, written in C++20.
The framework detects which world object the player is aiming at and delegates *all* reaction
behaviour (visual feedback, input handling, what happens on use) to that object through a shared
polymorphic interface. It ships with three demonstration object types that prove the framework end to end.

The design is inspired by the interaction system in *Prey* (Arkane Studios, 2017); it is an original
reimplementation, not derived from any Arkane/Bethesda code or assets.

## What it does

- **Detection (per type).** A dispatcher component on the player pawn runs an asynchronous camera
  raycast and identifies the currently aimed-at interactable. The detection distance is configurable
  *per object type*, not globally.
- **Passive highlight.** Interactable objects can opt in to a subtle, pulsing highlight shown whenever
  they are in view, independent of the raycast (a per-mesh overlay material).
- **Delegated reaction.** The framework stays type-agnostic: each object decides whether it reacts,
  what cursor/prompt to show, whether the action is currently allowed, and what happens on input,
  via a small polymorphic interface. Reaction logic lives in composable helper components, never in
  the framework core.

### Three demonstration implementations

- **Screen** - a cursor projects onto a UI rendered on the object's surface; the player clicks it.
- **Pickup** - a free-physics object the player can grab, carry in front of the camera, drop, and throw.
- **Rich prompt** - a text prompt with one or more action options and object-side validation
  (e.g. a locked state that disables the action), executed on key press.

Targets singleplayer only (no replication).

## Building and running

1. Install Unreal Engine 5.7 and a C++ toolchain (Visual Studio 2022 with the "Game development with C++"
   workload, or JetBrains Rider).
2. Right-click `BachelorsThesis.uproject` -> **Generate Visual Studio project files** (or open the
   `.uproject` directly in Rider).
3. Build the editor target, then open `BachelorsThesis.uproject`.
4. Press **Play** to enter the demo level. Controls: **WASD** to move, **mouse** to look, **F** to
   interact (grab/drop a pickup, click a screen, open the rich-prompt object). Other bindings live in
   the project's Input Mapping Contexts under `Content`.

> Note: the internal project/module is named `BachelorsThesis` (the repository name differs). All
> framework types use the `BT` prefix (`ABT...`, `UBT...`, `IBT.../UBT...`, `FBT...`, `EBT...`).

## Code structure

All C++ lives under `Source/BachelorsThesis/`, organised by layer:

- `Framework/` - the type-agnostic core: interfaces (`IBTInteractable`, `IBTInteractableSubscriber`,
  `IBTInteractor`), the interactable component, and the dispatcher.
- `ReactionHelpers/` - composable reaction components (two abstract bases + one concrete helper per
  demonstration variant).
- `PlayerServices/` - player-side aggregating services (input, UI) plus the C++ UMG widgets.
- `Highlight/` - the FR-2 passive-highlight component.
- `DemoActors/` - the three demonstration actors.
- `DataModel/` - shared structs/enums (prompt model, binding handle, cursor mode).
- `Tests/` - Unreal Automation tests.

The project also retains some unmodified First Person Template starter content; the interaction system
itself is the `BT`-prefixed code above.

## Tests

Unreal Automation tests cover the dispatcher's detection/transition logic and each variant's reaction
path. Run them from **Tools -> Session Frontend -> Automation** (filter `BachelorsThesis.Interaction`),
or headless:

```
UnrealEditor-Cmd BachelorsThesis.uproject -ExecCmds="Automation RunTests BachelorsThesis;Quit" -unattended -nopause -nullrhi
```
